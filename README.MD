# CareGuide RAG API

CareGuide is a healthcare document question-answering API built with Python, FastAPI and Claude.

Users can upload PDF or TXT documents and ask questions about their contents. The application retrieves relevant passages and instructs Claude to answer only from that context with source citations.

> **Disclaimer:** CareGuide provides document-based information only and is not a substitute for professional medical advice.

## Features

- PDF and TXT document upload
- Text extraction and validation
- Configurable overlapping text chunking
- TF-IDF vectorization
- Cosine-similarity retrieval
- Configurable top-k context selection
- Claude-powered grounded answers
- Document and chunk citations
- Healthcare safety prompt
- Interactive Swagger API documentation
- Automated tests

## RAG Pipeline

```text
Document upload
    ↓
PDF/TXT text extraction
    ↓
Text cleaning and overlapping chunking
    ↓
TF-IDF vectorization
    ↓
Cosine-similarity top-k retrieval
    ↓
Grounded prompt construction
    ↓
Claude answer with source citations
```

## Setup

### 1. Clone the repository

```bash
git clone https://github.com/tprasath40/careguide-rag.git
cd careguide-rag
```

### 2. Create a virtual environment

```bash
python -m venv .venv
```

Activate it on Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Activate it on macOS or Linux:

```bash
source .venv/bin/activate
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Configure Claude

Create a `.env` file using `.env.example` as the reference:

```env
ANTHROPIC_API_KEY=your_anthropic_api_key
CLAUDE_MODEL=claude-haiku-4-5
```

Never commit the real `.env` file or API key.

### 5. Run the application

```bash
uvicorn app.main:app --reload
```

Open the Swagger documentation:

```text
http://127.0.0.1:8000/docs
```

## API Endpoints

### Health check

```http
GET /health
```

Example response:

```json
{
  "status": "healthy",
  "service": "careguide-rag"
}
```

### Upload and index a document

```http
POST /documents/upload
```

Supported document formats:

- PDF
- TXT

The endpoint:

1. Validates the uploaded document.
2. Extracts its text.
3. Cleans and splits the text into overlapping chunks.
4. Creates TF-IDF vectors for retrieval.
5. Stores the document chunks in memory.

Example response:

```json
{
  "filename": "healthcare-guide.pdf",
  "characters": 6200,
  "pages": 3,
  "chunks_created": 16,
  "message": "Document indexed successfully"
}
```

### Ask a question

```http
POST /query
```

Example request:

```json
{
  "question": "What information does the document provide?",
  "top_k": 3
}
```

The response includes:

- A grounded answer generated by Claude
- Retrieved document chunks
- Filename and chunk citations
- Similarity scores
- Healthcare information disclaimer

## How Retrieval Works

The uploaded document is split into overlapping chunks. Each chunk is converted into a TF-IDF vector.

When a user asks a question:

1. The question is converted into a TF-IDF vector.
2. Cosine similarity is calculated against all stored document chunks.
3. The top-k matching chunks are selected.
4. Those chunks are supplied to Claude as grounded context.
5. Claude is instructed to answer only from the retrieved context.
6. The response includes document and chunk citations.

## Design Decisions

### Why use overlapping chunks?

Overlap helps preserve information that crosses chunk boundaries. The current default uses 500-character chunks with a 100-character overlap.

The overlap improves context continuity, although it also increases the number of indexed chunks.

### Why use TF-IDF for the MVP?

TF-IDF provides lightweight, fast and explainable local retrieval without requiring a large embedding-model download or an external vector database.

A future iteration will introduce dense semantic embeddings while retaining TF-IDF as part of a hybrid retrieval strategy.

### Why return citations?

Filename and chunk identifiers make answers traceable. Users can inspect the retrieved passages and verify whether Claude's answer is grounded in the uploaded document.

### Why use top-k retrieval?

Sending only the most relevant chunks:

- Reduces unnecessary token usage
- Improves response latency
- Limits irrelevant context
- Reduces the chance of unsupported answers

However, a very small `top_k` may miss useful information, while a very large value may introduce noise.

## Healthcare Safety

Claude is instructed to:

- Answer only from the supplied document context
- Avoid inventing medical facts
- Avoid providing a diagnosis
- Clearly state when the available context is insufficient
- Cite relevant document chunks

The API also returns a disclaimer explaining that the response is not a substitute for professional medical advice.

## Current Limitations

- Document vectors are stored in memory and disappear after restart.
- Scanned PDFs require OCR and are not currently supported.
- TF-IDF is based on lexical similarity rather than semantic similarity.
- The MVP runs as a single application process.
- Authentication and tenant isolation are not yet implemented.
- Document ingestion is synchronous.
- Retrieval-quality evaluation is not yet automated.
